# 完整形状导出优化与验收

固定基线：`90fcbbb3eb8767e8eaa9ada0f1293cfbe48c0689`。实施分支：`codex/export-20260926`。本次要求每种形状完整输出且可分类，不要求全集与分类各存一份。one-sided、前景/背景四邻接、stride8最小旋转代表的语义保持不变。

## 已实施的顺序与取舍

1. **单份分类流**：不再复制 `all_fixed`，以v2清单串接逻辑全集。n=6有效载荷从6,575,433,792字节减至3,287,716,896字节。`global_index`绑定数据集ID及清单顺序，不能跨运行沿用。
2. **BFS旋转优化**：直接180°旋转；非方形排除不可能成为最小代表的朝向；每个父形状复用四向旋转。仍保留canonical与Fixed BFS作为对照。
3. **前沿状态图回溯**：逐格0/1决策；仅共享拓扑和后缀可行性表，每条前缀仍携带自己的mask。按精确包围盒枚举 `height≤width`，通过四边触达和C4最小代表筛选，互斥前缀交给Rayon。按宽共享拓扑图，无全局形状去重表。测量胜出后成为默认导出路线。
4. **真正Redelmeier参考实现**：半平面锚点、按值继承untried/forbidden、u128域覆盖最多66格。串行，内存更低，但n=5明显慢于frontier，保留为显式参考路线，不设为默认。
5. **原生流式ZIP**：每槽256 KiB缓冲，`zip`/`flate2`的Rust后端；直接生成分块条目，完成后发布 `.zip`，无需先写裸数据再压缩。默认等级1。保留 `--compression-backend 7z`，它在本机有更好的压缩率。

Jensen式DP的总数不包含实际形状；本次frontier仅把其状态压缩思想用于后缀剪枝，仍遍历每个输出路径。纯计数约2.2ms的历史结果不包含形状生成、写盘或压缩。

## 测量口径

Windows x86_64，AMD Ryzen 9 7940HX，Rust 1.97.1，release可移植编译，未启用target-cpu=native。基准显式设置 `RAYON_NUM_THREADS`，各候选交替执行，无并发重负载。n=5预热一次后3次测量；旋转第二阶段使用5次。表中为中位数，内存为该组最大Job峰值提交内存。n=6只执行各路线单次，无预热，不能称为中位数或稳定上界。

整进程时间从受限启动器CreateProcess前到程序退出，包含启动、枚举、输出和所选压缩。Job内存包括外部压缩子进程，不等于RSS或系统文件缓存。输出位于本机C盘；裸输出没有逐文件fsync，不能将时间解释为断电持久化时间。原生ZIP在完成归档时sync_all。硬资源上限由Windows Job脚本执行，直接运行CLI不自动限制。

原生ZIP的算法时间包含边枚举边压缩；`ZIP收尾耗时`只计尾部缓冲、中央目录和发布。外部7z的算法时间不含随后单独的压缩阶段。跨后端比较以整进程时间为准。

### 完整性验收

- n≤4独立坐标/洪泛oracle比对四条枚举路线的完整集合和分类。
- n=5 canonical/frontier/Redelmeier，以及最终frontier的raw、ZIP0/1/9，均与原版520,818个唯一形状及8个分类全集相等。
- n=6裸输出逐条进入256个磁盘桶，完整u64掩码排序查重（散列仅分桶，不用指纹替代相等比较）。每条独立检查非空、归一化、包围盒、前景四连通、四旋转最小值、背景四邻接洞分类；精确边长分类数与已知差分计数一致。全部通过，128 MiB/180秒上限下验收12.414秒、峰值约53.01 MiB。
- n=6 ZIP全部条目解压读至EOF，通过CRC及字节数核验；解码结果再次经过上述独立完整验收，13.759秒、峰值约53.01 MiB，全部通过。完整合法唯一集合的条数等于独立DP总数，因而没有遗漏。
- 独立验收器小规模夹具覆盖正确输入、跨文件重复、断连、错误洞类别（含真洞误放无洞）、非最小旋转代表、残缺7字节。单独读取ZIP信息并不能替代这些验收。
- 独立审查发现并修复验收脚本未检查额外物理副本的问题：两个验证器现拒绝 `all_fixed`、越界分类和清单外条目。追加副本的RED/GREEN夹具通过，真实n=6 raw/ZIP物理白名单复核通过。逐形状验收核心未改变，复用上述全量证据。
- 最终54项Release、54项Debug及8项Python回归通过；普通测试未枚举n=6。

## 复现

```powershell
cd rust
cargo build --release --locked
./scripts/measure-export.ps1 -Exe ./target/release/room-count.exe -N 5 -Mode raw
./scripts/measure-export.ps1 -Exe ./target/release/room-count.exe -N 5 -Mode zip

# 本次已有n=6授权；脚本默认128 MiB、60秒、8线程，各次数据保留
./scripts/measure-export.ps1 -Exe ./target/release/room-count.exe -N 6 -Mode raw
./scripts/measure-export.ps1 -Exe ./target/release/room-count.exe -N 6 -Mode zip

# 标准库独立验收器，只接受分类裸文件；scratch必须新建或空目录
rustc -O ./scripts/verify-export.rs -o ./target/verify-export.exe
# 在Windows Job限制下执行此exe；n=6会额外写约3.29GB分桶文件
# 参数：<dataset-root> <scratch-new-dir> <n>
```

有界导出脚本检查全部n行计数、清单、分类精确计数和物理字节数，保存EXE/脚本/清单SHA；它不宣称独立集合验收。n=3 raw/nativeZIP/7z ZIP0成功。负向测试：16 MiB nativeZIP收到内存事件且程序非零；7z ZIP1在128 MiB下程序虽退出0但出现资源限制事件，脚本仍正确拒绝成功，没有提升预算重跑。
